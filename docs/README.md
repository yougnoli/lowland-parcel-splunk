# Project documentation

Good documentation is part of the project, like on a real one. Write it here, in this folder, in
the code editor, and commit it to `dev` like any other file. Your Tech Lead reads it in your pull
request and tells you what is clear and what is missing.

| File | What goes in it |
| --- | --- |
| [project-overview.md](project-overview.md) | What the end client needs and what this app delivers |
| [data-sources.md](data-sources.md) | Every data source: where it comes from, how it gets into Splunk |
| [decisions.md](decisions.md) | Choices you made and why, so a colleague does not have to guess |
| [runbook.md](runbook.md) | How to check that everything works, and what to do when it does not |

Write for a colleague who joins next month and has never seen this project.
